依赖组是什么意思？

把同一功能、需要配套适配或验证的 PR 归到一组，方便安排处理顺序。

例如 G16 是“设置导航、搜索与组件入口”。

同组不等于必须全部合入；具体前置关系和处理顺序，请看各 PR 的原因与完整解决方式。

权重如何评估？

权重是本地采用优先级，范围 1–10 分，越高越值得优先评估。PR 分数由同步评审者综合判断（可由 AI 辅助），网页不自动打分；目前没有加权求和公式。

评估依据：问题有多严重、与你的 macOS 插件和现有工作流程有多相关、影响多少常用场景，以及是否支撑其他重要功能。改动行数或社区热度不直接决定分数。

分档参考：9–10 分，关键可靠性或核心流程；7–8 分，常用功能的重要修复或增强；5–6 分，常规体验和效率改善；3–4 分，低频场景或维护；1–2 分，本地价值较低或属于排除范围。历史分数保留当时判断，未按此分档重新评分。

高分仍可能暂缓：例如协作流程很有价值，但要保留本地并行会话和项目卡逻辑，需要先完成适配。能否采用还要看状态、差异、依赖与验证。

社区设计主题取关联实现 PR 的最高分；没有关联实现 PR 时显示 1 分作为占位，表示尚无 PR 评分依据。单项 PR 直接显示自己的分数。
