# 群成员上下文展示与会话接续（讨论稿）

## 目标

1. 查看群成员时就能知道各自使用的模型、推理强度和本群会话还用了多少上下文。
2. 在群详情能查看本群成员的上下文概览，并在无需完整保留对话细节时，用摘要承接后续工作。

## 需求

- **R1 成员列表**　在现有角色说明下增加一行小字，例如「模型名 · 高推理 · 上下文 68%」。模型和强度优先取本群会话实际使用的值。仅有配置值时标明来源；模型不支持推理强度和用量尚未上报分别呈现。
- **R2 群上下文**　群当前会话对应 `room.sessionId`，成员在本群的当前会话对应 `room.sessions[botId]`。群自身只转发消息，无模型窗口。群详情只在各成员行显示占用，列表上方仅放会话接续入口。
- **R2.1 百分比**　建议沿用当前会话统计的口径，用已用上下文除以模型上下文窗口。每行只读对应当前段；缺少读数显示「暂无数据」。换段触发线还要考虑回复预留，两种百分比的基准可能不同。
- **R3 摘要换段**　现有上下文管家会判断工作是否告一段落，选择原段压缩或换段。正常换段已支持把交接笔记、近期原文和历史线索带入新段；溢出时可能没有笔记。讨论中的新增选择是让用户表达「接下来可以凭摘要继续」，以及这项选择作用于哪个会话。
- **R3.1 群级选择入口（已确认）**　用户在群内选择接续方式，每种方式旁都有问号。悬浮显示适用场景、触发时机及对后续对话的影响；键盘聚焦或触屏点按也能阅读，查看说明不会改变选择。
- **R3.2 选项和说明（建议文案）**　入口放在群详情的成员列表上方。保留现有的「由系统判断」作为默认项；另外提供「本次带摘要换段」操作和「接近上限时自动带摘要换段」偏好。前者执行一次，后者持续生效。执行前展示受影响的会话。**自动接续的作用范围（已确认）**：每位成员在本群的当前会话共用本群偏好，各自按自己的占用独立触发换段。该偏好仅在本群生效。
  - **由系统判断 (?)**　适合连续排查、讨论还没结束时使用。接近上限后，系统根据工作进度决定在当前会话压缩后继续，或在合适的停顿开启新段。
  - **本次带摘要换段 (?)**　适合一个话题刚结束、想接着聊新话题。当前回复结束后，把交接摘要和近期消息带到新段；仅本次生效。
  - **接近上限时自动带摘要换段 (?)**　适合长时间无人值守、只需保留关键结论的工作。达到预警线后，在安全的轮次边界带摘要换段；更早的细节仍可在旧段查阅。
- **R3.3 摘要失败（建议）**　对用户选定的摘要换段，摘要生成失败时显示原因并保留原段；提供方已报溢出时沿用现有恢复机制，并明确本次是否携带摘要。
- **现有设计差异**　原设计默认淡化上下文管理。此次拟在群详情主动展示占用，并讨论用户可控的换段。上游 #1766 涉及压缩后的用量估计，本地另有群成员主动请求换段；同一会话同时触发时，应只换一次。见[上下文与记忆](../../../docs/plans/2026-10-09-context-and-memory.md)、[群聊设计](../../../docs/plans/2026-10-07-group-chat.md)及[上游跟踪记录](../../../upstream-changelog.md)。

## 用户可见结果

- [ ] **O1（R1、R2）** 同一成员在两个群使用不同上下文时，打开各群能看到各自的占用；列表上方只提供接续设置。
- [ ] **O2（R2.1）** 新段尚未返回用量时显示暂无数据，获得读数后显示新段的占用。
- [ ] **O3（R3，候选行为）** 指定某一成员接续后，该成员在本群的新段可复述旧段的决定和未完成工作，旧段可查。群自身和其他成员继续使用各自原段。

- [ ] **O4（R3.1、R3.2）** 在群里查看每个选项的问号，能区分系统判断、仅执行一次和持续生效，并看到受影响的会话。仅查看说明时，原选择保持不变。

- [ ] **O5（R3.2）** 启用自动接续后，若只有 ETL 开发在本群的会话达到预警线，仅该会话带摘要换段。群自身、小圈、ETL 开发的私聊及它在其他群的会话继续使用原段。群自身仅转发消息，无模型预警线。

## 群历史归档

已确认的结果是将选中的历史从主聊天收起，允许查阅和恢复。建议操作如下。

1. 在一轮讨论的菜单提供三种归档方式。
   - 「归档这一轮」只选中当前这轮已结束的讨论。
   - 「选择多轮…」进入多选模式，可勾选不连续的已结束讨论，也可取消勾选。确认按钮显示「归档所选 N 轮」。
   - 「归档此轮之前的所有讨论」以所点的这轮为界，选中本群内时间更早、已结束且尚未归档的全部讨论，包含尚未加载的历史。保留作为分界的这一轮。
   - 执行前显示选中轮数；整轮归档发起消息、成员回复和进度。没有符合条件的轮次时禁用归档操作。取消后主聊天保持原样。
2. 主聊天收起该轮；群详情提供「已归档」入口，以日期和首条消息定位。打开后可阅读完整讨论；群搜索命中时标注「已归档」。
3. 选择「恢复到群聊」后回到原来的时间位置。原消息序号、引用和任务来源保持有效。归档只调整展示，不改变成员已读上下文，也不触发换段。

归档标记按群持久保存，正文继续由原群会话和消息账本提供。
