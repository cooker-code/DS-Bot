# 管理员扫描与原卡交接恢复

接单先保存规范化标题、需求、验收，再尝试交接。卡片不依赖投递成功才保存，也不因失败退出待处理收件列表后失去管理入口。

宿主在接单保存、任命或更换助理、重载后扫描无计划且无执行轮次的原卡。它向空闲管理员发送一条群级批次通知；管理员通过 `project_task scan` 逐项解释原因，对可重试卡调用 `retry_handoff`。批次通知不绑定某一 taskId，因此管理员能在本群同一轮处理多张独立原卡。已有计划与执行仍走原流程。

| 对象 | 持久位置 | 内容 |
| --- | --- | --- |
| 规范正文 | 原任务的 title、goal、acceptance | 发送失败也保留完整正文 |
| 卡片交接 | tasks.extra_json.managementHandoff | id、toId、sourceSeq、documentKey、sessionId、status、attempts、at、deliveredAt、error、nextAttemptAt |
| 管理员通知 | rooms.extra_json.projectHandoffScan | 当前管理员、批次指纹、固定消息 ID 与投递回执；不公开内部指纹 |
| 正式派工和开工 | 原卡 task_plans、task_rounds | 助理建计划、派工，执行者 start 后记录 startedAt |

不新增表，也不直接维护日用 SQLite。使用既有宿主写锁、事务及 extra_json 存储。

发送前保存固定消息身份；不确定结果先查当前和历史会话的队列及持久事件。相同目标、来源和正文复用回执，正文修订生成新交接；入队前核对当前角色及记录身份，阻止已被新版替代的旧正文迟到。旧回执只用于说明最近发送，`scan/unassigned` 返回当前正文的可重试状态。

临时失败按 30 秒间隔提醒管理员检查，最多自动提醒三轮；实际重试由管理员执行。缺正文且原材料不可读、助理绑定无效等不可自动重试情形仍通知管理员解释。已有在途投递、计划、执行、完成及明确澄清不重复派工。关闭时取消定时器并等待正在扫描和发送的任务，避免释放宿主后继续写入。

回滚旧插件会保留扩展字段和既有执行轮次，旧版本不会消费新字段；回滚不撤销已经派发的工作。
