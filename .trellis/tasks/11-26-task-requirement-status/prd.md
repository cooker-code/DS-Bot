# Goal

1. 用户能够区分原始需求、管理员整理后的需求及后续修改，按实际需求版本查阅历史。
2. 用户能够为已在其他 agent 完成的阻塞或失败任务更正卡片状态，并留下原因。

# Requirements

## R1 需求版本修复

- R1.1 首条用户原文及附件为 v1。管理员首次保存不同的整理内容为 v2；后续需求正文或图片的实际修改继续递增。重复保存同一内容不增版。
- R1.2 详情编辑、管理员委派和计划中的需求修改共用需求历史语义。执行计划单独计版本，只调整节点时不增加需求版本。
- R1.3 旧卡缺少快照且有明确原始收件时恢复 v1。无法恢复的中间编辑次数不猜测。新派工记录实际需求版本，历史派工不按时间猜测版本。

## R2 用户更正任务状态

- R2.1 在任务详情的“分支与工作树”下方显示任务状态。只有当前阻塞、失败的任务有“更改状态”入口；只读宿主不提供编辑。
- R2.2 选择不同的新状态、填写非空原因后才可保存。用户可取消，失败时保留草稿和错误，保存成功显示反馈。
- R2.3 保存状态、原因、时间和操作者，历史可展开查阅；列表、详情和重启回读使用同一状态。并发状态变化时拒绝旧请求。
- R2.4 保留原派工、回执、阻塞和失败记录，不启动或停止 Bot，不伪造节点认可。手动完成主卡时按原规则同步完成多级关联子卡，取消不级联。若后续有新的自动执行或计划状态，恢复自动状态，手动记录继续保留。

# User-visible Outcomes

- [ ] O1 用户原文 v1、管理员整理后 v2、再修改 v3 均可选择查看；只改计划与重复保存不增加需求版本。（R1.1、R1.2）
- [ ] O2 sentence_score 旧卡的原文可以恢复为 v1，现有四条整理需求显示为下一版；无法恢复的中间修改次数明确未知。（R1.3）
- [ ] O3 阻塞、失败卡在分支下方可更改状态；其他状态与只读场景无编辑入口。（R2.1）
- [ ] O4 原因必填，取消不保存；失败保留草稿；保存后状态与原因可回读，刷新和重启后仍存在。（R2.2、R2.3）
- [ ] O5 手动更正不改执行历史，旧状态或存储失败不会留下半次修改，后续实际执行可重新推进状态。（R2.3、R2.4）
