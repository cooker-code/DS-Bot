# 从执行记录回答项目进度

确认项目、覆盖范围和观察时间。查询一个 task 时，从其需求、计划、当前节点和最近一轮开始。在已配置 DS Bot 项目 task 的群里用 `project_task` 的 `list` 取得范围，用 `read` 加 `taskId` 取相应记录。通过已授权的操作者 API 查指定群时，先用 `project-task-list {roomId}` 取 task 和待处理收件，再用 `project-task-detail {roomId,taskId}` 读轮次。按实际可见权限读取。未启用这些入口时用已有交接、候选和验收记录，标明样本范围、未知项与最近核实时间。

- **单个 task。** 分开报告已派发、已开工、已提交、独立验收及发布状态。给出负责人、最近一次实质进展、阻塞或等待条件、下一步由谁推进。并行节点分别核对执行者，列表中最后一轮的负责人只能说明那一轮。
- **积压和负荷。** 在同一时点按 task 标识去重，列出等待分配、可开工、执行中、阻塞和待复核的数量及最早等待时长。统计 Bot 负荷时数它当前承担的节点，区分实际执行和等待依赖。明确 task 数与节点数各自的分母。缺起始时间时保留未知。
- **错误和质量。** 在同一计划版本、节点内核对实际轮次、重试原因与独立复核结论。送达回执和重复通知只记一次。把环境错误、等待、实现缺陷和验收退回分别计数。没有复核样本时只报告错误事实。比较成员时列出样本数、口径、难度与共用依赖对结论的影响。
- **给出依据。** 用具体 task、节点、轮次、候选及证据入口支持判断。用户问现状时直接回答。跨 task 的专题按项目约定写入 Trellis 或指定文档，常规完成报告由助理汇总。查看进度时使用只读操作，改派、重试和发布按原流程另行处理。
