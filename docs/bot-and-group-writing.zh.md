# Bot 简介与群公告写作规范

| 字段 | 正文长度（含 Markdown） | 首行内容 |
| --- | --- | --- |
| Bot 简介 | 250～400 字，优先 250～360 字 | 找它做什么，交付什么 |
| 群公告 | 600～1000 字 | 第一条可执行的群内约定 |

Bot 简介以一句岗位定位起头，再分条写清接单输入、工作步骤、交付证据和异常交接。明确独立复核、授权和资源清理等本岗位必须执行的边界。用字优先留给会改变执行结果的条件。名册展示首行摘要，Bot 自身使用完整指令。[现有岗位简介](bot-role-profiles.zh.md) · [详细岗位手册](bot-role-handbook.zh.md)

群公告从具体操作或触发条件写起，按收件、派工、验证等实际步骤分段。只保留换人后仍适用的规则，例如重试前查哪个回执、谁可以独立复核、哪些操作需另行授权。成员名单和任命查当前群设置，每项工作的负责人查当前任务卡。省去群名释义、成员介绍和岗位职责清单。临时进度与当轮验收样本写在原任务卡。

正文使用 Markdown 真实换行，段间留空行，列表用 `- `。计数采用保存正文的 Unicode 字符数，包含空格、标点、Markdown 符号及 LF 换行；文档里的对象标题不进入配置。上述区间是写作标准。维护时先对照原规则核对流程，再按对象回读实际保存的全文与字数。

以下为现有群公告。

## engineering-memory

**受理与归属**

- 用户可直接提出新需求。咨询有证据就答；需要实施时，沿原收件交接原文、附件、目标和验收条件。补图、变更和返工沿原卡继续。归属不清时先查本群卡片，只向用户确认影响交付的取舍。
- 群内回报以半角方括号写项目卡实际标题，例如 `[修复群公告预览]`。工具调用使用本群 project_task 返回的 taskId，外部卡号仅作来源参考。

**派工与恢复**

- 在本群会话核对当前成员与卡片，用 plan 保存节点、负责人、依赖和验收条件，派出就绪节点。读取卡片核对当前轮次，再用 message_bot 指定准确的 Bot 名称，带 taskId、card_round、reply_to=user 和 request_id，由插件传递原文与附件。
- 同一工作只走一个派工渠道。结果不明先查送达；重试复用原请求标识及参数。执行人在收到派工的会话核对目录、工作树、分支和基线，以 start 确认开工。受阻时说明原因、已有产物和所缺输入，可独立的节点继续；接管前核实原执行已停止写入。

**交付与验收**

- 在分配的工作树实现、自测，按授权本地提交，以 submit 交回候选提交、实际测试命令与结果、复验方法和遗留项。在原卡核对同版证据，退回时说明失败位置和预期，认可后推进依赖节点。
- 末节点获认可后向用户说明结果。合并、发布和送验按具体授权执行；明确要求人工终验时，由用户本人确认。

## DS-Bot

**收件与派工**

- 咨询有证据就答，新需求保留原文、附件、目标和验收条件；有助理时用 delegate 交接原收件。补充与返工沿原卡。群内用半角方括号写卡片实际标题，工具使用本群 taskId。外部卡号只作来源参考。
- 保存节点、负责人、依赖与验收条件，先派就绪节点。读回卡号、当前轮次和负责人，再从本群会话用 message_bot 正式派工，带 taskId、card_round、reply_to=user、request_id。送达不明先查回执，重试沿用原参数和请求标识。

**开发与验证**

- 派工时绑定目录和分支；执行人首次写入前核对实际工作树、基线和授权范围，用 start 登记开工。dev 可开发和本地提交，main/master 只读；分配错误先更正，保留用户已有改动。按项目约定用 Trellis 记录需求，执行轮次归 DS Bot 卡片。
- 遵循仓库指引，行为变更先查设计，设置或接口变更先查 ds-bot-doc。仅用 DSH 公开插件接口，能力缺失时说明缺口。客户端改源码并构建生成文件。测试使用隔离实例和模拟模型，保护密钥、令牌和 Cookie。
- 用 submit 交候选版本、实际测试结果、复验入口和遗留项。由非作者复核同版证据，分别记录代码完成、检查通过及实际加载。阻塞时推进独立节点，说明需补的最少输入。末节点获认可后向用户说明结果，用户明确要求时才等人工终验。推送、合并、本地部署、发布及破坏性操作遵循仓库规则和具体授权。

## 数据开发

**受理与协作**

- 咨询先查指标口径、字段来源或作业记录；需要改脚本、调度或数据时，再按授权范围登记任务。
- 接单时保留用户原文与附件，明确目标、范围、环境、授权和完成条件；已有信息能确定的问题直接处理。
- 补充信息和返工沿原任务继续，同一工作只经一个渠道派发；写入或发布前在原任务确认唯一执行人，避免重复改动或重复发布。
- 切换执行人时，在原任务交接完整候选版本、配置、依赖、测试证据和未完成项；候选发生变化时重新检查受影响部分。
- 工具可用时通过项目任务工具记录交接与证据；工具未实际配置时，不宣称已自动建卡或系统派工。
- 阻塞时说明已完成内容、具体缺口、影响及所需最少输入，继续推进不依赖该条件的已授权工作。

**验证与交付**

- 用实际证据区分实现完成、测试通过、发布受理与正式生效，不以执行过代替成功。
- 按项目要求执行上线前独立复核，作者自审、测试成功和审批通过均不能代替必要的独立复核；所需能力不可用时不得自行豁免。
- 最后节点获认可即可完成；仅用户明确要求时再交用户人工终验，退回沿原任务返工。
- 交付说明实际版本、验证入口、已核实范围和未完成事项。

**环境与授权**

- 本群配置项目目录为 `/Users/blank/wangliang/gitcode/data-analysis-template`；执行前确认各自实际工作目录，遵循该目录的项目指引和适用技能，不混用其他项目环境。
- 平台操作前加载适用技能，基于真实元数据，不虚构表字段；使用项目允许的 MCP 或 CLI，禁止回退到 TablePro MCP。
- 提交、合并、推送、生产数据改写、回刷、发布、删除及调度变更均按用户具体授权执行，不因角色分工自动获得操作授权。
- 不默认创建 Trellis task；仅在用户明确要求时启用，DS Bot 协作记录与 Trellis 任务分别处理。
- 平台或环境不明时先核对；保留无关数据、配置和已有改动。
