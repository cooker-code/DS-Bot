# 功能卡独立结单，Git 管理师异步集成本地 dev

2026-11-21 · 新版实施指令，自本次交接起替换「测试工程师合入 dev，合并后通知助理结单」。主聊天接续已有实现，保留有效的候选、测试证据和 Git 历史。相关设计见[项目任务派工](2026-11-19-project-task-dispatch.md)与[Git 管理师岗位说明](../bot-role-profiles.zh.md#git-管理师)。

## 从收件到结单

1. 小圈把用户原文、截图和验收要求正式交本群任务助理。需求清楚时一次收件即可推进。助理比较已有卡，能由同一修改覆盖的选主卡并关联其余卡，保留各自验收条件，只派一次开发；可独立交付的拆开，只登记实际依赖。
2. 开发从约定的 dev 基线在独立工作树、功能分支实现并自测，交回完整候选提交号、变更说明和自测证据。DSH 测试工程师独立检出该提交，按原卡验收并核对实际受测版本。失败时沿原卡退回开发，列复现步骤、预期、实际及修改意见。新提交重新绑定，复测变更影响的部分，并说明沿用哪些证据。
3. 任务助理核对全部约定验收项及独立测试通过的提交与开发交付一致。宿主在同一事务中保存功能结单与待集成记录，任一失败均回滚。卡号与完整候选号唯一，重复提交返回原记录。测试报告随卡保存，归档可随后进行。常规小改动至此结单；如某卡确需专项评审，规划时明确验收条件。
4. 卡面分别呈现功能和集成进度。功能完成后依次可见「待集成」「集成中」，遇阻显示「集成受阻」及原因、负责人和下一步。验证了实际合并提交后显示「已合入 dev」，附候选、合并提交和验证证据。

## 从领取到写回

- 为项目配置 Git 管理师。程序消费结单产生的记录，按依赖优先、同等条件按就绪顺序原子领取，防止并发重复执行。低频补扫仅修复漏项。单项受阻，跳过它及依赖它的项，继续处理其他就绪项。
- 通过项目本地 dev 的统一写入入口集成。在独立工作树从合并前 dev 试合并固定候选，对实际生成的提交执行针对性检查。更新 dev 时原子核对旧基线；若已推进，用新基线重试并验证新结果。保护在用工作树及未提交改动。
- 持久记录候选、合并前 dev、合并结果、实际受测提交的完整编号，以及验证范围与证据。留下足以在中断后识别本次尝试的记录。重启或领取超时先核对 Git 包含关系和已有回执。已合入且证据齐全则补回执；已合入但缺验证则显示待补验证，在对应合并快照补验。两种情况均避免重复合并。
- 常规成功自动完成，只写结构化回执。仅在冲突或证据需要判断时唤醒 Git 管理师做代码评审。规则可解的冲突由管理师处理并复测；需改功能实现的交对应开发，新候选重新独测和登记。产品行为互斥交助理协调。仅当证据证明原候选本身违反验收条件，助理才重开原卡并保留旧候选及验收历史。后续 dev 推进、跨卡回归和可选改进均保留原卡已有结论。
- 本次目标止于本地 dev。角色说明承载职责与判断原则；结单校验、事务、队列、领取互斥、Git 操作与恢复、回执及卡面均须落实到代码。实施时复用现有群库、派工和权限入口，更新对应接口契约。
