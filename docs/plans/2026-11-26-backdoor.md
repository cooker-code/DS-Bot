# 后门（Backdoor）：本机受限操作入口

## 名称与定位

本功能统一称为“后门”，英文定位名为 `backdoor`；原称“本机受限访问”或“本机操作入口”。它指当前账户可显式启停、仅开放指定 DS Bot 操作的 Unix socket 管理入口。

## 为什么

用户希望从 Codex 直接查询 DS Bot、修改简介和群公告，同时继续从 Dock 启动 Desktop。共享 DSH 登录凭据会授予更广的宿主操作权限。用户已选择仅授权 DS Bot，因此使用插件自己的本机受限入口，由操作系统账户权限控制访问。

## 已定的行为

- 入口默认关闭。当前账户用 `local_access.py enable/status/disable --desktop` 明确启停并查看实际状态；验证 Desktop 写锁 PID 与父进程归属后才定位日用团队。隔离或 Web 团队必须显式传 `--team-home`。
- 插件通过 Unix socket 接收 JSON 请求，不监听 TCP，不提取或保存 DSH 登录凭据。socket 目录为 0700、socket 为 0600；授权和发现文件均为 0600，包含它们的团队子目录为 0700。不接受符号链接或不安全权限。
- 首版仅允许 `state {}`、`update-bot {id,instructions}`、`update-room {id,notice}`、`project-task-list {roomId}`、`project-task-detail {roomId,taskId}`。所有字段必须符合调用说明。额外字段和所有其他操作在业务分派前拒绝。
- `state` 仅返回团队标识、修订、只读原因、Bot ID/名称/角色/简介，以及群 ID/名称/公告/成员/管理员。正文修改回执也投影至这组字段；项目卡查询复用现有结果。不给此入口增加供应商、密钥、连接器或浏览器配置读取。
- 操作复用 `rt.channelCall`，保留原业务校验、团队写锁、存储与生效动作。客户端核对发现文件 PID 与当前团队写锁 PID；服务端请求前检查写权。写后按原 ID 全文回读才报告保存成功。
- 简介和公告沿用原服务去掉首尾空白的行为，保留正文内部换行；回读比较的目标为约定的保存正文。
- 每次请求重新检查授权。撤销后尚未进入业务服务的请求被拒绝，发现文件和监听随之关闭；已开始保存的请求可以完成。启用选择跨宿主重启保留，socket 和发现文件每次重新生成并在正常退出时清理。
- 新版运行时可直接响应启用。插件尚未加载或仍为旧版时返回 `active:false,restartRequired:true`，用户自行从 Dock 重开，脚本不退出或重启 Desktop。
- HTTP 报文只接受 `/status` 和 `POST /api/bot`，正文上限 1 MiB，不接受浏览器 Origin 或 DSH Cookie/Authorization 头。CLI 不把登录材料、正文或响应全集写入诊断。

## 不做什么

不共享宿主操作员登录，不修改 DSH，不导出或签发 DSH Token/Cookie，不提供远程访问、MCP、模型推理兼容接口、Bot 创建删除、派工、消息发送或宿主设置修改。本入口用于已列出的本机管理动作，不代替暂缓的上游统一 API/Run 功能。

## 已知限制

操作系统权限识别的是当前 macOS 账户。同一账户的其他进程也能使用入口及启停文件，不能宣称只授权 Codex。它不防御已控制当前账户的恶意程序。

授权目录监视失败时停止本次入口并拒绝新请求，已排队的启用不得重新打开监听。命令会报告 `active:false,restartRequired:true`，需要用户在合适时间重开宿主。正常关闭会等待本次请求及 socket 清理完成。

宿主异常退出可能留下过时发现文件与 socket；客户端用写锁 PID 排除旧宿主，下一次启用由新宿主写新的发现信息。正常退出会清理自己拥有的资源，不删除其他宿主的监听。修改请求连接中断后结果可能未知，应先全文回读，不能自动重发。
