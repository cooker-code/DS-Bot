# DS Bot 群任务路由说明

群设置默认启用任务管理。开启后，DS Bot 按卡片区分群内工作。群管理员在本群的成员会话里用 `project_task` 建卡和读卡，使用 `message_bot` 派工。数据归 DS Bot 插件持有。产品分工、群上下文和存储说明见 [DS Bot 项目群的任务看板](bot-task-workflow.zh.md)。

## 为什么要加

假设群里正在验收卡 A 的导出功能，用户又提出卡 B 的分页问题，随后引用 A 的消息补发一张截图。三条消息都在同一个群里，甚至可能交给同一个 Bot。仅凭发言顺序，最新的截图很容易跟着 B 走。如果让所有新消息都排在队尾，正在验收 A 的 Bot 又会错过本轮需要的截图。

按卡片识别消息后，截图可以直接补进 A 的当前执行，分页问题则带着 B 的编号排队。用户也可以直接提新需求，卡片归属由群管理员处理。

## 一条消息怎样走到负责人

1. **识别归属。** 在群输入框「＋ → 关联任务」或任务详情「继续此任务」选择已有卡。消息元数据保存任务 ID。普通正文、引用和单独的「继续」不会绑定任务。新收件有自己的 intakeId；受理后以正式卡跟踪，缺少必要信息时建卡并标记待澄清。
2. **接收新需求。** 在启用了任务路由且有管理员的群里，系统将新需求连同附件送到当前管理员在本群的会话。转交成功时群里只显示用户原消息，失败时提示原因。管理员用 `project_task list` 查询本群成员和卡片。可以当场答复的问题用 `chat` 记录处理理由并在群里回答；用户要求建卡跟踪或交付需要执行和验收的成果时用 `plan` 建卡；为同一需求补充材料时用 `attach` 归入原卡。
3. **派给负责人。** 管理员读回卡号、负责人和本轮计划，在本群的成员会话使用 `message_bot` 带上卡号和轮次正式派工。宿主核对群成员、管理员及轮次，将原始需求、真实附件和验收条件送入负责人会话。负责人显式调用 `project_task start` 确认开工，`submit` 交回结果。群任务面板展示这些状态。
4. **带着卡号继续工作。** 接续已建卡的需求时，管理员会收到原文、原附件、当前轮次和最近的提交结果，可按原卡复核或交接。同卡补充可以送进负责 Bot 正在进行的那次执行，其他卡的群消息按编号排队。Bot 沿用原有会话和权限。进度和结果也带着原卡编号返回。

用户追问“为什么这个没建 task”时，管理员先核对用户引用的原话。没有引用时，可在本次收件中用 `project_task context` 读取消息发出前最多八条本群公开发言，包括已有的收件分类、理由和卡片关联。引用更早的发言时可用 `query` 按原文字面检索。紧邻的上一条用户发言若已按问答处理，其原话和处理理由也会随新收件送达。管理员说明当时的依据；有多个可能的指代时，先问用户指哪句话。回引已按问答处理的收件提出新问题时，原问答的分类记录仍可查阅。

## 存储与验证

群记录保存项目卡和派工轮次。消息账本保存需求及附件引用，请求回执处理重复派工。同一卡号也随在途任务和群队列保存。当前实现和自动检查见[单插件收件与派工](../ds-bot/test/group-work.test.js)、[任务归属](../ds-bot/test/groups.test.js)和[模拟模型冒烟场景](../ds-bot/dev/smoke.mjs)。
