# DS Bot 群任务路由说明

项目群在公告中写入 `[taskId]` 后，DS Bot 按卡片区分群内工作。群管理员在自己的会话里用 `project_task` 建卡和读卡，使用 `message_bot` 派工。数据归 DS Bot 插件持有。产品分工、群上下文和存储说明见 [DS Bot 项目群的任务看板](bot-task-workflow.zh.md)。

## 为什么要加

假设群里正在验收卡 A 的导出功能，用户又提出卡 B 的分页问题，随后引用 A 的消息补发一张截图。三条消息都在同一个群里，甚至可能交给同一个 Bot。仅凭发言顺序，最新的截图很容易跟着 B 走。如果让所有新消息都排在队尾，正在验收 A 的 Bot 又会错过本轮需要的截图。

按卡片识别消息后，截图可以直接补进 A 的当前执行，分页问题则带着 B 的编号排队。用户也可以直接提新需求，卡片归属由群管理员处理。

## 一条消息怎样走到负责人

1. **识别归属。** 消息开头或者引用的原消息里有卡片编号时，沿用这张卡的 `taskId`。两处编号冲突就拒绝投递。用户直接发来的无编号需求先获得临时收件编号 `intakeId`，用于保留原文和附件，等待管理员确认对应的卡。
2. **接收新需求。** 在启用了任务路由且有管理员的群里，系统将新需求连同附件送到当前管理员的独立会话，群里留下转交回执。管理员用 `project_task list` 查询本群成员和卡片，使用 `assign` 建卡，或用 `attach` 将补充归入原卡。
3. **派给负责人。** 管理员读回卡号、负责人和本轮计划，在独立会话使用 `message_bot` 带上卡号和轮次正式派工。宿主核对群成员、管理员及轮次，将原始需求、真实附件和验收条件送入负责人会话。负责人显式调用 `project_task start` 确认开工，`submit` 交回结果。群任务面板展示这些状态。
4. **带着卡号继续工作。** 同卡补充可以送进负责 Bot 正在进行的那次执行，其他卡的群消息按编号排队。Bot 沿用原有会话和权限。系统保留通用指令，从任务历史中只选本卡的消息、工具结果和附件交给模型。进度和结果也带着原卡编号返回。

## 存储与验证

群记录保存项目卡和派工轮次。消息账本保存需求及附件引用，请求回执处理重复派工。同一卡号也随在途任务和群队列保存。当前实现和自动检查见[单插件收件与派工](../ds-bot/test/group-work.test.js)、[任务归属](../ds-bot/test/groups.test.js)和[模拟模型冒烟场景](../ds-bot/dev/smoke.mjs)。
